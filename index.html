后台是怎么进去的

没有“隐藏网址”这一说，只有“独立入口 + 权限校验”。

自己写一个 /admin 页面

和前台的 App 分开；用管理员账号 + 强密码 + 二次验证登录，后台接口逐个校验管理员权限。

实现成本中等

用托管服务的控制台

比如 Supabase / Firebase / 云数据库控制台：登录服务商的账号就能看表、改数据、导出备份。

操作方便，但数据仍归你负责

SSH 进服务器 + 数据库客户端

直接用命令行或 Navicat 连数据库，能看到、能改、也能一次误删整张表。

权限最大，风险最高

“汇聚到你这里”到底意味着什么

密码哈希只是其中一小格，真正汇聚的是一整套行为画像。

你能看到

  • 用户名、学校、注册时间、最近活跃时间
  • 已掌握词条、答题记录、正确率、错题
  • IP 归属地、设备型号、登录会话
  • 密码哈希（能比对，不能还原）
  • 游客进度合并记录、注销申请

你仍然看不到

  • 用户的明文密码（实现正确的前提下）
  • 用户设备上没上传的内容
  • 用户从未提供的信息

但你实际上能做到

  • 重置任意用户密码、强制下线
  • 导出全部数据、恢复旧备份（含历史记录）
  • 删除账号，或绕过界面直接改数据库
  • 查看每一个人的学习行为

因此你要承担

  • 数据库泄露、备份泄露、误操作的责任
  • 隐私政策、注销、数据删除、泄露告知
  • 未成年人信息的额外保护义务
  • 24 小时可用性和长期维护

本页面是本地单文件演示，不联网、不写数据库；关闭后不保留任何操作。
